# The Price of a Place in Line

Equilibrium Daily, No. 0001, 8 November 2026. Section: Mechanism Design.

- Page: https://equilibriumdaily.github.io/notes/0001.html
- Full note with proof (PDF): https://equilibriumdaily.github.io/pdf/0001.pdf
- Drafted by an AI model and reviewed by a person before publication.

## Intuition

A regulator must decide whose infrastructure project goes first but cannot verify how valuable or reliable a developer's project is. Collateral is then the only tool that makes developers report truthfully. The note computes the exact deposit needed for efficient priority, shows that it exceeds what either pivotal developer gains from priority, and shows that a priority lottery is optimal when collateral is scarcer.

## Result

Efficient truthful implementation with individual rationality is possible if and only if the escrow limit satisfies $L \ge K$, where $K = \frac{c[s(1-r)a - r(1-s)b]}{s-r}$; moreover $K > csa$, so the required collateral exceeds both pivotal types' expected gains from priority.

## Summary

A developer whose project value $v \in \{a,b\}$ and completion probability $p \in \{r,s\}$ are private competes for priority against a fallback developer with a publicly known type; the second project is attempted only if the first fails, and project values are unverifiable. The regulator can use only an escrow of at most $L$, refunded according to reports, the priority lottery and observed completion outcomes. Efficiency gives priority exactly to high-value reports, although the pivotal high-value type $h=(b,r)$ values priority less than the low-value type $\ell=(a,s)$. When $L < K$, every DSIC mechanism has expected welfare loss at least $\min\{\mu_h\Delta_h, \mu_\ell(-\Delta_\ell)\}(1-L/K)_+$, and a priority lottery attains this bound for a family of two-point priors. The implementing deposit refunds more after failure than after success.
